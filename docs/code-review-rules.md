# StackChan 代码审查规则

本文是 Codex Code Review 的详细规则源。根 `AGENTS.md` 负责路由；审查时只应用与变更文件
匹配的章节。发现应说明触发条件、实际后果和最小安全修复方向，避免把建议性重构当成缺陷。

## 全仓库

- 检查变更是否泄露 Wi-Fi 凭据、Tailscale auth key、私钥、令牌、生产地址、设备身份或完整控制面响应。
- 检查跨模块接口是否保持兼容；新增依赖必须固定版本或 commit，并保留来源、许可证和兼容性证据。
- 不把 OpenSpec、README 或注释中的目标状态误判为已经实现的行为；事实冲突应指出具体代码路径。
- 不审查生成内容本身。若 `sdkconfig`、`build/`、下载组件或生成文件被直接修改，应指出其事实源或生成器。
- 测试缺口只在改动引入可复现风险且现有 CI 无法覆盖时报告，并说明需要证明的行为。

## `firmware/` 与 `remote/code/`

- 检查 task、timer、event handler、socket、buffer、NVS handle 和网络对象在成功、失败、重连及关闭路径上的所有权是否一致，避免泄漏、重复释放或 use-after-free。
- ESP-IDF event callback 不得执行无界等待、长时间网络操作或可能阻塞系统 event loop 的工作。
- 检查 allocation、task 创建、队列操作和 ESP-IDF API 返回值；非核心网络能力失败时应可降级，不得无意触发整机 abort。
- 网络改动必须保持官方 Wi-Fi、OTA、XiaoZhi 和 App Center 的所有权边界；Tailnet 路由不能误接管普通公网流量。
- 对包长、字节序、索引、MTU、分片和缓冲区边界进行严格验证；未经认证的数据不得更新可信 endpoint、peer 身份或路由状态。
- 凭据和密钥不得进入日志；NVS schema 或 key 名变更必须处理升级、缺失、损坏和恢复场景。
- ISR、回调和跨 task 共享状态必须满足对应同步约束；不要假设普通字段读写能够替代 ESP-IDF/lwIP 所需的线程安全边界。
- 涉及 Wi-Fi、BLE、音频、舵机、NVS、OTA 或 Tailnet 恢复时，编译通过不能代替真机验收；缺少必要证据时应指出未验证范围。

## `app/`

- 检查异步操作完成后 widget、controller 或 stream 的生命周期，避免对已释放状态进行更新。
- 检查权限拒绝、网络中断、设备离线和重复操作路径；错误状态必须可恢复且不能泄露凭据。
- 与固件或服务端通信的数据模型变更必须保持版本兼容，或提供明确迁移路径。

## `server/`

- 检查认证、授权和资源所有权是否在服务端强制执行，不能只依赖客户端字段或 UI 状态。
- 外部输入进入 SQL、文件、模板、命令或网络目标前必须经过类型、边界和权限验证。
- 数据库 schema、事务和并发更新应保持向后兼容与幂等性；失败路径不能留下部分提交状态。
- API 契约变化应同步处理固件和 App 消费方，或提供兼容窗口。

## `.github/` 与构建系统

- 检查工作流权限是否最小化，外部 Actions、镜像和工具链是否固定到可信版本或不可变身份。
- 不允许通过跳过测试、吞掉退出码或缩小必要验证范围来让 CI 变绿。
- 构建脚本不得依赖未记录的本机状态、凭据或仅在交互式 shell 中存在的环境。
